Insights & Analysis

Two-step model: first capture sampled operation events, then optionally run post-run explain enrichment on selected slow shapes.
Recommended patterns:
• Sampling only: lightweight slow-query profiling
• Sampling + Explain: full troubleshooting workflow
• Explain depends on retained sampled events (filters/pipelines for selected shapes)
1) Insights Capture (Retention & Sampling)
Controls what telemetry is captured and retained in memory for final post-run analysis.
2) Explain Enrichment (Post-Run)
Runs MongoDB explain after workload completion for selected slow shapes. This does not run during measured workload execution.
Explain requires eligible retained samples from Insights Capture. If sampling/retention are too low, explain may be unavailable for some shapes.
executionStats provides real examined/returned evidence and better troubleshooting recommendations.
Default keeps explain focused on high-severity slow groups to reduce low-value attempts and timeout pressure.
